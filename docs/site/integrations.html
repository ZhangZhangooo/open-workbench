支持列表

接得上什么

下面每一项都是实测跑通的，不是「即将支持」。 没列出来的不一定不行，但至少我没亲手验过 —— 所以不写。

AI 模型 聊天通道 推送 打印机 文档数据 平台

AI 模型

  • Ollama 云端
  • Ollama 本地
  • GPT-OSS 120B
  • Qwen 2.5
  • Llama
  • 任意 OpenAI 兼容接口

看图需要视觉模型。实测 Ollama 云端 17 个模型里只有 gemma4:31b 能看图，其他明确报「不支持图片」。

聊天通道

  • 微信（经企业微信）
  • Telegram
  • Discord
  • Slack
  • 飞书
  • Signal
  • iMessage
  • Matrix
  • Teams
  • Line
  • SMS
  • Mattermost

全部走官方接口，不碰逆向协议 —— 逆向微信协议是封号最快的方式。已实测落地的是微信（企业微信自建应用 + 微信插件）。

推送连接器

  • PushPlus
  • Server酱
  • 企业微信
  • Webhook（任意 URL）
  • SMTP 邮件

结果能推到任何地方。停用不必删，每次推送都留日志。

3D 打印机

  • OctoPrint
  • Klipper / Moonraker
  • PrusaLink

局域网自动扫描（认特征路径，不瞎猜），能看进度、喷头与热床温度、剩余时间，能暂停继续取消。

普通打印机

  • Windows 打印队列
  • IPP 直连
  • IPPS（TLS）
  • WSD 设备

自动发现本机打印机，可指定份数、纸张、单双面。内容自动转 PDF 后调起系统打印框。

文档与数据

  • PDF
  • DOCX
  • XLSX
  • PPTX
  • Markdown
  • IMAP / SMTP
  • SQLite（本地）
  • JSON

数据落在本机 data/app.db，可导出备份。邮件正文读过一次就缓存到本机，之后离线也能搜。

说在前面：三个已知限制

自动送印走系统打印框

试过 11 条直写通道（winspool / IPP / IPPS / GDI / Chrome kiosk）， 现代 IPP/WSD 打印机普遍拒绝应用层直写。最后用系统打印框 —— 走厂商驱动， 最稳，代价是你要点一下确认。

3D 打印只验到协议层

用模拟器验的（OctoPrint / Klipper / PrusaLink 各自的真实响应）。 我没有 3D 打印机，所以真机没跑通过 —— 这一条我不含糊。

翻译只完成 10%

界面语言跟随系统，中英双语。英文词条译了约 200 条（共 2048）， 没译到的仍显示中文而不是变空白。
